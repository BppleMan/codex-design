## Design first. Build from a product you can use.

![Codex Design overview — concept illustration](https://geeduzbsatvodnlijqfs.supabase.co/storage/v1/object/public/product-media/69836a39-4ab4-4ed9-ac59-31de87ddc660/screenshots/1791732537418-t2zb.png)

Codex Design turns an idea, a rough brief, or an existing product into a high-fidelity, interactive Web prototype. Explore the product with Codex, refine its behavior and visual design in the browser, and build a clear product definition from the decisions you make.

## What you can do

- Start with your own idea. A complete PRD or existing codebase is optional.
- Clarify decisions that affect the design, using native questions when the Codex environment supports them.
- Simulate Web, macOS, iOS, Android, or plugin experiences inside one Web project.
- Explore coherent mock interactions, shared state, and relevant empty, loading, failure, and recovery scenarios.
- Refine color, typography, density, layout, and key states together using Codex's built-in browser annotations.
- Capture scope, decisions, assumptions, behavior, and visual references alongside the prototype.
- When you choose to implement, translate an approved scope into your application and compare it against the confirmed prototype.

## How to start

Install the complete package into your Codex skills directory, then ask:

```text
Use $codex-design. I want to make [your idea]. Help me turn it into an interactive prototype with mock data.
```

## Environment and scope

Designed for Codex environments with local skill support, file and command access, and tools to run and review Web prototypes. The core instructions are in Chinese; supporting documentation includes English and Chinese.

Host interfaces are simulated in the browser. Production integration begins when you explicitly request it for a confirmed version. Mock behavior and browser checks remain separate from real backend and native-platform verification.
