# 可复用原型底座

## 何时使用

需要创建新 Web 原型，且 React/TypeScript 适合当前任务时，可用 `assets/prototype-starter`。已有原型优先局部增强，其他技术栈也可实现同样的行为契约。不要为了套底座重写已确认设计。

从 Skill 根目录运行：

```sh
python3 scripts/create_prototype.py /path/to/new-project --name "My product"
```

路径是用户指定的新目录；命令拒绝覆盖已有路径。进入输出目录后运行 `npm ci`，再运行 `npm run dev -- --host 127.0.0.1`。读取实际输出的预览地址并在可用内置浏览器中打开，不假定固定端口。需要 Node.js 24+。

这是前端示例工程，没有 API、账号、真实支付或远端同步；场景中的异步操作也是本地模拟。

## 结构与改造点

| 路径 | 负责什么 |
| --- | --- |
| `src/project.json` | 项目身份、名字及产品修订 |
| `src/studio/Simulator.tsx` | Web、macOS、iOS、Android 外壳与开关/尺寸控制 |
| `src/studio/Studio.tsx` | 模拟器外的预览、候选、调节与记录工作区 |
| `src/studio/model.ts` | 候选定义、视觉参数、快照校验、导出与恢复 |
| `src/example/model.ts` | 示例业务数据和状态转换；新项目替换这里 |
| `src/example/FeedbackApp.tsx` | 示例产品界面；新项目按目标设计 |
| `docs/product-definition.md` | 示例功能边界，创建新项目时同步改写 |

这些相对路径描述生成工程，不是 Skill 文档之间的链接。

先用用户的目标替换示例业务、文案、数据及功能边界。Threadline 的反馈流程、候选配色、布局和排除项只是示范，不是所有产品的默认定义。修改候选或状态结构时，同步维护导入校验、测试和格式版本。

## 两种独立状态

共享业务数据支持模拟器联动；导航、当前选择和未提交表单按模拟器独立。关闭模拟器不应擅自清除业务数据。若产品实际需要其他生命周期语义，按用户的规则改造。

模拟场景覆盖该产品的关键条件，不机械添加账号/订阅/多端等无关能力。模板提供日常、空白、离线、加载和错误，用户可通过 UI 恢复。异步完成必须匹配仍有效的请求，取消或换场景后不能由旧回调改写新状态。

## 三类外部控制

- 业务场景：改变模拟环境或夹具，明确是否重置数据。
- 视觉实验：调整候选来源、布局、密度和少量高影响参数。
- 交付记录：保存实验快照或范围确认，导入/导出，恢复工作副本。

使用 Codex 内置批注，底座不提供自建标注系统。宿主已有同等能力时可复用它，保留统一的数据依据。

## 验证

运行 `npm test` 和 `npm run build`。在浏览器验证实际流程、联动、异常恢复、参数与业务状态隔离、保存后的不可变性以及导出再导入。使用 `?qa=1` 隔离测试存储，不修改用户评审中的记录。

框架检查只能证明代码条件；目标尺寸的截图、交互结果、用户确认和真实宿主验证分别记录。设备外壳只是模拟，不等同于真机。
