# 从一个点子走到可交付依据

这个案例由 [原型底座](../assets/prototype-starter/README.md)直接运行。它演示方法，不代表所有产品都应采用反馈收件箱或同一视觉。

先看[示例产品定义](../assets/prototype-starter/docs/product-definition.md)中的三轮追问及假设：它们逐步确定使用者、反馈对象、状态和离线边界。真实任务按信息缺口决定是否追问；需要提问时等待用户实际回答，不能把示例回答代入。

接着在工作台比较候选，进入真实可操作的预览；用场景控制暴露异常，用多个模拟器检验数据归属，用视觉参数比较密度和布局。用户在 Codex 内置浏览器直接批注，代理按范围修改。

将实验快照与范围确认分别保存。确认的结果不仅是截图，还包括候选来源、参数、mock 数据、范围、排除项及未决问题。JSON 用于重现，Markdown 用于对照实现。

本次验证应分别报告原型构建、代码行为检查、浏览器实际操作和用户确认。自动化中填写“QA 模拟”的确认记录不能转成真实用户定稿。
